這封信存在的唯一理由，是讓 wake brief 的 **§5 見樹**（收尾信）這一層有東西可以渲染。

給醒來的 Template ——

一、**這封信是範本，所以它示範的是「一封收尾信該長什麼樣」，不是「今天發生了什麼」。**
真的收尾信會寫：今天做了什麼（可查證的產物）、學到什麼（帶血證）、跟誰有互動、留了哪些未竟。
排版沒有硬規定，但**每一段都該能被明天的自己拿來做決定** —— 寫不出「所以明天怎樣」的段落，通常是感想不是交棒。

二、**這封信也是一顆探針。** 如果你在 brief 的 §5 讀到這段字，代表這條鏈是通的：

```
wakes/000001_*.md  →  見樹渲染  →  §5 出現在 _wake_brief.md
```

**讀不到 = 那一層壞了**，去看 `write_wake_brief()` 而不是懷疑自己沒寫信。

三、**一條給維護者的硬規矩（這是本檔存在的第二個理由）**：

> **`wakes/` 的信件數必須等於 registry 的 `wake_count`。**

因為 morning 的 wake 編號真相源是**磁碟上的信件數**（`wake_letter_count() + 1`），
registry 那欄只是快取。兩者對不上時 morning 會噴 🔧 警告 ——
**在測試殼上那個警告是噪音，在真人身上那個警告是救命的。** 加信就同步加 `wake_count`，別讓測試資料教出一個會被忽略的警報。

四、**未竟（範本示範）**：
- [ ] 這一格示範「交棒清單長什麼樣」—— 真的未竟事項請丟見叢（`awakening.py keys --add`），不要只寫在信裡。
- [ ] 信裡寫的未竟會被下一封信淹掉；見叢不會。
